# ディスク保守時のリセット経路（準備段階）

`A04BR3_DISK_SERVICING=1` はビルド時に `A04BR3_TEST_CYCLE=1` と
`A04BR3_CPU_1300=1` を拒否する。既定値は0であり、通常ビルドを変更しない。
記録付きFDビルダーでも同じ組合せを拒否し、manifestに値を記録する。

これは既知の2経路を除外する設定であり、watchdogや外部リセットが全て停止した
証明ではない。現在の正本はAArch64のUniXNU向け構成であり、実測済みのARM32
Windows RT用EDK2実験とは同一ではない。この設定を付けただけのFDをWindowsで
起動可能と判断したり、DISMに用いたりしない。

`A04BR3_TEST_CYCLE=1` ではSECで31秒watchdogを設定し、DXEは120秒以内の間だけ
給餌する。ExitBootServicesでは31秒を再設定して給餌を終了する。`CPU_1300=1`
かつ試験サイクル無効の場合も、周波数変更中に一時的にwatchdogを使う。
両方0の場合のSEC処理は既存のMT8167コードでwatchdogを停止するが、後続の
ファームウェア・OS・他コア・ハードウェアが変更しないことは未検証。

Windowsデータ領域への書込みを伴わない適合確認として、固定された正本コミットと依存関係から
ARM32構成を生成し、その出自を記録した後、同一構成のWinPEで開始時と
ExitBootServices後のwatchdog状態、420秒以上の待機、外部リセットサービスの
排他を観測する必要がある。この候補はARM32への移植、watchdog状態の実測、
I2C1/ACPI、Windows WinPE動作をまだ実証していない。許可済みの無人実機検証を
実施し、その結果を記録する。出自と実機証拠、および既存データ保護の準備が
整うまではオフラインDISMを開始しない。

ホスト側のASan/UBSan試験 `Tests/check_recovery.py` は試験サイクルの実C制御と、
両方0のSECでのMODE書込み・再armなしを模擬する。MMIOとRTCは代替実装であり、
ハードウェア状態、全リセット源、Windows動作を証明しない。
